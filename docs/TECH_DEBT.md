# 📉 Technical Debt & Roadmap

Этот документ отслеживает технические компромиссы, принятые для обеспечения совместимости с движком игры, и планы по развитию бота.

## 🔴 Высокий приоритет (Architecture & Stability)

### 1. `core.py` Monolith (God Object)

Файл `core.py` начинает накапливать слишком много ответственности: навигация, инвентарь, обертки действий, математика путей.

- **Симптом:** Сложно найти нужную функцию утилиты; риск циклических зависимостей при расширении.
- **План:**
  - Разделить `core.py` на подмодули (виртуально, если игра не поддерживает импорты папок, или физически с последующим бандлингом):
    - `core/movement.py` (Move, Pathfinding)
    - `core/actions.py` (Plant, Harvest, Water)
    - `core/inventory.py` (Checks, Buying)

### 2. Inconsistent Crop Implementation

В папке `src/farming/` смешаны подходы: одни культуры реализованы как одиночные файлы (`carrot.py`), другие — как модули стратегий (`tree/`).

- **Проблема:** Отсутствие единого интерфейса запуска. `main.py` (точка входа) должна знать детали реализации каждой культуры.
- **План:** Стандартизировать интерфейс.
  - Каждая культура должна быть папкой `src/farming/[name]/`.
  - В каждой папке должен быть `__init__.py` (или `entry.py`), экспортирующий единую функцию `run()`.
  - Простые скрипты (`carrot.py`) должны стать `carrot/baseline.py`.

## 🟡 Средний приоритет (Optimization & DX)

### 1. Hardcoded Grid Logic

Некоторые алгоритмы в `core.py` неявно полагаются на размер поля или другие константы, вместо использования `get_world_size()`.

- **Риск:** Бот сломается при разблокировке расширения фермы.
- **Задача:** Провести аудит всех циклов `range()` и заменить магические числа на вызовы API.

### 2. Manual Dependency Injection for Types

Сейчас `builtins.pyi` обновляется вручную при открытии новых фич игры.

- **Симптом:** Если в игре появляется `Items.Gold`, анализатор ругается, пока мы не добавим это в `typings`.
- **План:** Написать скрипт-сканер (если возможно) или задокументировать процесс обновления `TypeAlias` (ItemType, EntityType) в `CONTRIBUTING.md`.

### 3. Отсутствие обработки "Умирания" (Emergency)

Логика `emergency.py` существует, но не интегрирована глубоко во все стратегии.

- **Проблема:** Если дрон застревает или заканчивается вода посреди цикла `smarty.py`, бот может зависнуть.
- **План:** Внедрить декораторы или контекстные менеджеры (совместимые со старым Python) для безопасного выполнения операций с ресурсами.

## 🟢 Низкий приоритет

### 1. Refactoring `generate_closed_path`

Алгоритм генерации пути "змейкой" работает, но не оптимален для всех стратегий (например, для полива 4x4 подсолнухов).

- **План:** Реализовать разные паттерны обхода (Spiral, Blocks) и передавать их как аргумент в стратегии.

### 2. Type Comments Verbosity

Использование `# type: (...)` загромождает код.

- **План:** Исследовать возможность написания кода на современном Python с последующей транспиляцией в старый синтаксис перед копированием в игру (strip-hints скрипт).

### 3. Modern Tooling Infrastructure (uv)

Текущий проект полагается на хаотичный набор инструментов или системный Python.

- **Проблема:** Отсутствие воспроизводимости среды разработки (версии линтеров, форматтеров). Медленная установка зависимостей.
- **План:**
  - Внедрить **uv** как единый менеджер проекта (вместо pip/poetry).
  - Настроить `uv run ruff check` для линтинга (замена pylint/flake8).
  - Настроить `uv run pytest` для запуска локальных юнит-тестов (с использованием `mock_env`).
  - Создать `justfile` или `Makefile` для унификации команд (`make test`, `make lint`).
