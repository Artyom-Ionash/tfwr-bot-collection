# Архитектура проекта

Проект представляет собой **коллекцию ботов для компьютерной игры**, реализующей ограниченную версию интерпретатора Python. Архитектура построена на принципах **стратегического разделения (Strategy Pattern)** и **строгой статической типизации** в условиях отсутствия прямой поддержки типов игровым движком.

## 🐍 Файловая структура

Структура прототипа довольно слабая, но она есть.

### Ключевые элементы

1.  **`typings/builtins.pyi`** (Interface Layer)
    - **Что это:** "Контракт" с игровым движком. Описывает глобальные функции (`move`, `harvest`), константы и классы игры.
    - **Роль:** Обеспечивает базовый статический анализ в VS Code, не влияя на исполняемый код.
    - **Принцип:** _Mocking the Environment_. Объясняем анализатору API игры.

2.  **`core.py`** (Abstraction Layer)
    - **Что это:** Высокоуровневые абстракции над примитивами игры.
    - **Функции:** `move_to`, `generate_closed_path`, безопасные обертки над действиями.
    - **Где использовать:** Во всех стратегиях фермерства (`src/farming/*`).
    - **Правило:** Здесь живут _универсальные_ механики, не привязанные к конкретной культуре.

3.  **`emergency.py`** (Resilience Layer)
    - **Что это:** Жадная версия `clear()`.
    - **Роль:** Принудительный сбор урожая на карте.

## 🏗 Принципы слоев (Boundaries)

Слои как таковые практически не оформлены, но независимые скрипты управления ботами собраны вместе.

### 1. Farming Strategies (`src/farming/`)

Основной слой бизнес-логики. Каждая культура (или группа задач) — это отдельный модуль.

#### 📂 Complex Strategies (`src/farming/[crop]/`)

Для культур со сложной механикой, требующей разных подходов или оптимизаций.

- **Структура:** Папка с несколькими реализациями.
- **`baseline.py`:** Базовая, надежная, но медленная реализация (простое и понятное решение).
- **`smarty.py`:** Оптимизированная, экспериментальная или сложная логика (например, с учетом узоров роста).
- _Примеры:_ `dinosaur/`, `tree/`.

### 2. Typings & Config (`typings/`, `pyrightconfig.json`)

Слой конфигурации среды разработки.

- **Назначение:** Обеспечить подобие статической типизации в проекте на Python 3.x (Legacy Syntax).
- **Zero-Runtime Overhead:** Эти файлы игнорируются игрой, но критичны для Pylance.

## 🧠 Принципы проектирования (Design Principles)

### 1. Type Safety over Syntax

Мы используем **Type Comments** (PEP 484) вместо современных аннотаций, чтобы сохранить совместимость со старым интерпретатором игры.

- ✅ **Правильно:**
  ```python
  # type: (int, int) -> None
  def move_to(x, y): ...
  ```
